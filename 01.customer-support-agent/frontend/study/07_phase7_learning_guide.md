# Phase 7 학습 가이드 — 마무리 (앱 셸 · 네비게이션 · 폴리시) (선택)

**목표**: 4개 화면을 하나의 앱으로 묶고 다듬는다.

> 선택 단계. 새 기능보다 "흩어진 화면을 제품처럼" 연결하고 빈/로딩/에러 상태를 채우는 작업.

---

## 화면 지도

```
/                  채팅 (메인)              ← Phase 2~3
/admin/documents   관리자 문서 업로드        ← Phase 4
/admin/refunds     관리자 환불 승인 큐       ← Phase 5
/refunds           내 환불 조회 (사용자)     ← Phase 6
```

---

## Step 1: 공통 레이아웃 / 네비게이션 (10분)

- `app/layout.tsx`에 공통 헤더/네비게이션(채팅 · 관리자 · 내 환불) 추가.
- App Router에서 페이지 간 이동은 `next/link`의 `<Link>` 사용.

> ⚠️ `frontend/AGENTS.md`: "이건 네가 알던 Next.js가 아니다 — 코드 작성 전
> `node_modules/next/dist/docs/`의 해당 가이드를 먼저 읽어라." 레이아웃/라우팅 컨벤션이
> 훈련 데이터와 다를 수 있으니 Next 16 가이드를 먼저 확인하세요.

---

## Step 2: 상태 처리 다듬기 (10분)

각 화면에 빠진 상태를 채웁니다:
- **로딩**: 스피너/스켈레톤.
- **에러**: `ApiError` 메시지 표시 + 재시도.
- **빈 상태**: "데이터 없음" 안내.
- **반응형**: 모바일/데스크톱 레이아웃.
- **기본 접근성**: 버튼 라벨, 포커스, 키보드 조작.

---

## Step 3: (선택) 운영 점검 (5분)

- LangSmith 트레이스가 정상 기록되는지 확인(백엔드 연동).
- 환경변수(`NEXT_PUBLIC_API_URL`)가 빌드/런타임에서 올바른지 확인.
- `npm run build` 최종 통과(Phase 2 선결 과제가 잔존하지 않는지).

---

## 검증

- [ ] 4개 화면을 네비게이션으로 오갈 수 있다.
- [ ] 전체 플로우가 끊김 없이 동작:
  **업로드(Phase 4) → 채팅 질문(Phase 2) → 환불 신청·본인확인(Phase 3) → 관리자 승인(Phase 5) → 사용자 조회(Phase 6).**
- [ ] 각 화면의 로딩/에러/빈 상태가 자연스럽다.
- [ ] `npm run build` 통과.

---

## 검증 체크리스트 (개념)
- [ ] App Router의 공통 레이아웃/`<Link>` 네비게이션을 안다.
- [ ] 로딩/에러/빈 상태를 일관되게 처리하는 패턴을 안다.
- [ ] 전체 사용자 여정을 한 번에 설명할 수 있다.
